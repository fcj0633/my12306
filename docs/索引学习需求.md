# 五、每个重点索引必须按照“八步法”讲解

对于重要索引，请使用下面的结构逐个解释。

例如：

# 示例：`t_order.uk_order_sn(order_sn)`

## 1. 对应业务是什么

先用业务语言说明。

例如：

```text
ticket 服务创建订单后，
orderSn 是整个购票链路的业务订单号。

Ticket 可能因为 Feign 超时重复调用创建订单，
所以 Order 需要通过 orderSn 判断订单是否已经创建。
```

---

## 2. 实际 SQL 是什么

必须从源码中找到真实查询。

例如：

```sql
SELECT ...
FROM t_order
WHERE order_sn = ?;
```

以及：

```text
INSERT t_order ...
```

不要只写抽象 SQL。

---

## 3. 如果没有索引，会发生什么

这是重点。

例如：

```text
如果 t_order 有 100 万行，
没有 order_sn 索引时：

MySQL 无法通过 B+Tree 定位目标记录，
只能扫描大量记录。

复杂度由近似 O(logN)
退化为 O(N) 扫描。
```

但不要只说复杂度。

请继续解释：

- InnoDB 会扫描什么
- 会读取多少页
- 为什么数据量小时可能感觉不到
- 为什么数据量上升后问题明显

---

## 4. 为什么选择这个索引

解释：

```text
为什么 order_sn 适合索引
```

需要结合：

- 区分度
- 查询频率
- 是否等值查询
- 是否作为业务主键
- 是否参与状态机
- 是否存在重复调用

---

## 5. 为什么是 UNIQUE，而不是普通 INDEX

例如：

```text
UNIQUE(order_sn)
```

除了加速查询，还有：

> 数据库层面的业务一致性约束。

需要结合项目的幂等设计解释：

```text
业务代码：
先查 orderSn

数据库：
UNIQUE 最终并发兜底
```

解释：

> 为什么“先查后插”本身不能保证并发安全。

可以给出两个线程同时：

```text
SELECT 不存在
SELECT 不存在
INSERT
INSERT
```

的过程。

---

## 6. B+Tree 在这里到底怎么工作

这一部分必须比普通项目文档讲得更细。

不要一句：

> MySQL 使用 B+Tree，加快查询。

请解释：

如果：

```text
order_sn = O202600001
```

MySQL 如何：

```text
root page
↓
internal page
↓
leaf page
```

找到记录。

如果是二级索引：

说明叶子节点存的是什么。

例如 InnoDB：

```text
二级索引叶子节点：
order_sn → 主键 id
```

然后是否需要：

```text
回表
```

必须说明。

## 8. 这个索引的代价

不要把索引写成“越多越好”。

必须解释：

```text
INSERT
UPDATE
DELETE
```

为什么会因为维护 B+Tree 增加成本。

同时解释：

- 磁盘占用

- 写放大
- 唯一索引检查

然后结合当前业务判断：

> 为什么即使有这些成本，这个索引仍然值得。

# 六、联合索引必须重点讲“为什么列顺序这样设计”

这是我最需要学习的部分。

```text

```

或者你建议：

```text

```

必须详细解释：

为什么：

```text

```

可能合理，而：


必须结合真实 SQL：

```sql

AND order_time < ?

LIMIT 500
```

解释：

1. 等值条件为什么通常更适合放前面
2. 范围查询发生后，后面的索引列怎么使用
3. 最左前缀原则在这个查询中的实际表现
4. `ORDER BY id` 能否利用这个索引
5. 如果增加 id：

```text
(status, order_time, id)
```

到底解决什么问题
6. 它是否真的比两个单列索引：

```text
INDEX(status)
INDEX(order_time)
```

更合适

请不要只说：

> 联合索引遵循最左前缀原则。

我要看到实际 SQL 的执行分析。

# 十三、结合“锁”讲索引

这是非常重要的部分。




```text

```

# 二十、真实性要求

必须严格区分：

```text
【项目当前实现】
【根据源码推导】
【优化建议】
【理论知识】
```

如果源码里：

```text
没有某个索引
```

绝对不要写：

> 项目使用了这个索引。

应该写：

> 当前项目没有该索引，这是一个可以考虑的优化设计。

如果没有真实：

```text
EXPLAIN
压测数据
```

也不能伪造。
