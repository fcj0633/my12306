## 二、目录结构

```text
docs/5-后续开发规划/
├── 00-规划/            【A 规划类】怎么想、做什么
├── 01-设计分析/        【编码前的分析】动手之前读
├── 02-结果与结论/      【实测数字与结论】改完之后读
├── 03-交接与索引/      【给下一个执行方】
├── start-services.ps1  【B 环境类】打包 + 启动 + 健康检查
├── stop-services.ps1   按 PID 文件停止
├── smoke/              【C 验证类】run-smoke.ps1 九步端到端冒烟
└── baseline/           【D 压测类 + E 数据产物】压测脚本与跑出来的证据同目录
```

**一句话记住分组**：**A 告诉你要做什么，B/C/D 是工具，E 是工具跑出来的证据。只有 E 里的数字能改变 A 里的结论。**

逐文件说明（含"什么时候该用哪一个"）见 [`03-交接与索引/文档地图与D1基线性能分析.md`](03-交接与索引/文档地图与D1基线性能分析.md) 第二、三章。

## 三、为什么 `baseline/` 和 `smoke/` 没有分子文件夹

它们**不是文档目录，而是可执行的工作目录**，动它们会直接打断脚本：

| 约束 | 位置 | 说明 |
| --- | --- | --- |
| **服务脚本写死了同级 `baseline\`** | `start-services.ps1:10-11`、`stop-services.ps1:5` | `Join-Path $PSScriptRoot "baseline\logs"` / `"baseline\service-pids.json"` |
| **服务脚本的 ProjectRoot 依赖目录层级** | `start-services.ps1:3` | `"$PSScriptRoot '..\..\12306\my12306'"` —— 往下挪一层就会指错 |
| **压测脚本之间用 `$PSScriptRoot` 互相定位** | `baseline/*.ps1` | 整个 `baseline/` 作为单元移动是安全的，**拆开就会断** |
| **`baseline/` 同时是 D 类（脚本）和 E 类（产物）的家** | `baseline/results/`、`baseline/logs/` | 脚本按固定相对路径读写这些产物，拆开需要改多处 |

## 四、引用约定

本目录内文档的相对引用**以所在文件为基准**。处于子文件夹中的文档引用根目录下的 `baseline/`、`smoke/` 时写作 `../baseline/`、`../smoke/`。

跨目录引用（如 `docs/6-面试复习/` 引用本目录）统一使用**仓库根相对**写法 `docs/5-后续开发规划/<子文件夹>/<文件>.md`。

> 例外：`03-交接与索引/文档地图与D1基线性能分析.md` 第二章的目录树**不带 `../`** —— 那棵树描述的是从本目录看出去的完整结构，不是从该文件出发的导航路径。
