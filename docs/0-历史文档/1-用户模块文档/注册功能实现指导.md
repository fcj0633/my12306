# 注册功能实现指导（v1）

> 本文档是**实现指导**，不是成品代码。每个步骤给出「目标 → 涉及文件 → 关键代码片段 → 要点」，代码片段为骨架级示例，需要你按自己的代码风格补全。实现完成后可按第五节验收。
>
> 方案已确认：轻量 Result 统一响应、jakarta 注解校验、BCrypt 密码、事务 + 唯一索引兜底并发、配套 has-username 接口。不做分布式锁、布隆过滤器、Redis、责任链（列为 v2）。

## 一、功能目标与前置条件

**目标**：实现 `POST /api/user-service/register`，走通「参数校验 → 用户名可用性检查 → 手机号/邮箱唯一性检查 → BCrypt 加密 → 事务落表 → 统一响应」完整链路；顺带实现 `GET /api/user-service/has-username`（注册页实时校验，与注册共用同一可用性逻辑）。

**已就绪（本次不动）**：

- 数据库 `12306_user`：t_user、t_user_phone、t_user_mail、t_user_reuse、t_user_deletion 五张表已建，联合唯一索引就位。
- 数据层（`edu.swu.fcj.my12306.biz.userservice`）：
  - `dao.entity`：BaseDO + UserDO、UserPhoneDO、UserMailDO、UserReuseDO、UserDeletionDO
  - `dao.mapper`：UserMapper、UserPhoneMapper、UserMailMapper、UserReuseMapper、UserDeletionMapper
  - `dto.req`：UserRegisterReqDTO、UserLoginReqDTO、UserDeletionReqDTO
  - `dto.resp`：UserRegisterRespDTO、UserLoginRespDTO、UserQueryRespDTO
- 依赖：web、mybatis-plus-spring-boot3-starter、mysql、lombok；application.yml 已配置数据源与逻辑删除。

**本次新增**：`common`（Result/Results/ServiceException/GlobalExceptionHandler）、`config.PasswordConfig`、`service.UserLoginService` + `service.impl.UserLoginServiceImpl`、`controller.UserInfoController`，以及集成测试。

## 二、功能流程

```mermaid
flowchart TD
    A[POST /api/user-service/register<br/>UserRegisterReqDTO] --> B[@Valid 参数校验<br/>非空 + 格式]
    B -->|失败| B1[GlobalExceptionHandler<br/>返回失败 Result]
    B -->|通过| C{用户名可用性<br/>t_user 无 del_flag=0 的同名记录}
    C -->|不可用| C1[抛出: 用户名已存在]
    C -->|可用| D{手机号 / 邮箱唯一性预检}
    D -->|已注册| D1[抛出: 手机号或邮箱已注册]
    D -->|未注册| E[BCrypt 加密密码]
    E --> F[开启事务]
    F --> G[插入 t_user]
    F --> H[插入 t_user_phone]
    F --> I[插入 t_user_mail<br/>mail 非空才插]
    G & H & I --> J{插入成功?}
    J -->|撞唯一索引| K[捕获 DuplicateKeyException<br/>转为业务异常, 事务回滚]
    J -->|成功| L[提交事务]
    L --> M[返回 UserRegisterRespDTO<br/>username / realName / phone]
```

**复用表语义（重要）**：t_user_reuse 在 v1 只作"注销后复用"的记录表，**不参与可用性判定**。可用性只看 t_user 中是否存在 `del_flag=0` 的同名记录。v2 引入布隆过滤器 + Redis 复用集合后，再按原项目方式联动。

## 三、实现步骤

### 第 1 步：补依赖

**涉及文件**：`services/user-services/pom.xml`

```xml
<dependency>
    <groupId>org.springframework.security</groupId>
    <artifactId>spring-security-crypto</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-test</artifactId>
    <scope>test</scope>
</dependency>
```

**要点**：spring-security-crypto 只提供 BCrypt 等加密工具，不会引入整套 Spring Security 拦截器；版本由 Spring Boot 父 pom 管理，不需要写版本号。

### 第 2 步：轻量统一响应

**涉及文件**：`biz.userservice.common` 包下新建 4 个类。

```java
// Result.java —— 统一响应体
@Data
@Accessors(chain = true)
public class Result<T> {
    public static final String SUCCESS_CODE = "0";
    private String code;
    private String message;
    private T data;
}
```

```java
// Results.java —— 成功响应的快捷方法
public final class Results {
    public static <T> Result<T> success(T data) {
        return new Result<T>().setCode(Result.SUCCESS_CODE).setData(data);
    }
}
```

```java
// ServiceException.java —— 业务异常
public class ServiceException extends RuntimeException {
    public ServiceException(String message) {
        super(message);
    }
}
```

```java
// GlobalExceptionHandler.java —— 统一异常出口
@RestControllerAdvice
public class GlobalExceptionHandler {
    @ExceptionHandler(ServiceException.class)
    public Result<Void> serviceException(ServiceException e) {
        return new Result<Void>().setCode("500").setMessage(e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> validException(MethodArgumentNotValidException e) {
        // 取第一个字段错误信息返回
    }

    @ExceptionHandler(Exception.class)
    public Result<Void> exception(Exception e) {
        return new Result<Void>().setCode("500").setMessage("系统异常");
    }
}
```

**要点**：v1 用字符串 code（"0" 成功 / "400" 参数错误 / "500" 业务或系统错误），不引入错误码枚举；后续要升级成原项目的 BaseErrorCode 体系时，只需替换常量来源。

### 第 3 步：DTO 校验注解

**涉及文件**：`dto/req/UserRegisterReqDTO.java`（加注解）、Controller 参数加 `@Valid`。

| 字段 | 注解 | 说明 |
| --- | --- | --- |
| username / password / realName / idCard / phone / mail | `@NotBlank` | 必填 |
| idType | `@NotNull` | 必填 |
| mail | `@Email` | 邮箱格式 |
| phone | `@Pattern(regexp = "^1[3-9]\\d{9}$")` | 手机号格式 |

```java
@NotBlank(message = "用户名不能为空")
private String username;
```

**要点**：校验失败由 GlobalExceptionHandler 的 `MethodArgumentNotValidException` 分支兜住，统一返回失败 Result，前端拿到 message 展示即可。

### 第 4 步：BCrypt 配置

**涉及文件**：`biz.userservice.config.PasswordConfig`

```java
@Configuration
public class PasswordConfig {
    @Bean
    public BCryptPasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}
```

**要点**：BCrypt 密文固定 60 位，与 t_user.password `varchar(60)` 匹配；encode 每次加盐，同一密码两次结果不同，属正常现象。

### 第 5 步：业务层

**涉及文件**：`service/UserLoginService.java`、`service/impl/UserLoginServiceImpl.java`

```java
public interface UserLoginService {
    Boolean hasUsername(String username);
    UserRegisterRespDTO register(UserRegisterReqDTO requestParam);
}
```

```java
@Service
@RequiredArgsConstructor
public class UserLoginServiceImpl implements UserLoginService {
    private final UserMapper userMapper;
    private final UserPhoneMapper userPhoneMapper;
    private final UserMailMapper userMailMapper;
    private final BCryptPasswordEncoder passwordEncoder;

    @Override
    public Boolean hasUsername(String username) {
        // 返回 true 表示可用：t_user 中不存在 del_flag=0 的同名记录
    }

    @Transactional(rollbackFor = Exception.class)
    @Override
    public UserRegisterRespDTO register(UserRegisterReqDTO requestParam) {
        // 1. 可用性预检：hasUsername 为 false → 抛"用户名已存在"
        // 2. phone 预检：t_user_phone 存在 del_flag=0 的同 phone → 抛"手机号已注册"
        // 3. mail 预检：t_user_mail 存在 del_flag=0 的同 mail → 抛"邮箱已注册"
        // 4. passwordEncoder.encode(requestParam.getPassword())
        // 5. 插入 UserDO / UserPhoneDO / UserMailDO（mail 非空才插）
        // 6. 捕获 DuplicateKeyException → 抛"用户名或联系方式已被注册"
        // 7. 组装 UserRegisterRespDTO(username / realName / phone) 返回
    }
}
```

**字段复制清单**（手动 set，暂不引入 BeanUtil）：

| 来源（UserRegisterReqDTO） | 目标（UserDO） | 备注 |
| --- | --- | --- |
| username / realName / idType / idCard / phone / mail / userType / postCode / address / region / telephone | 同名 | 直接复制 |
| password | password | **先 encode 再复制** |
| verifyState | verifyStatus | **字段名不同，注意映射** |

| 来源 | 目标 | 复制字段 |
| --- | --- | --- |
| UserRegisterReqDTO | UserPhoneDO | username、phone |
| UserRegisterReqDTO | UserMailDO | username、mail |

**要点**：

- 事务必须 `@Transactional(rollbackFor = Exception.class)`，保证任一插入失败整体回滚。
- 预检 + 唯一索引是**双保险**：预检给友好提示，唯一索引兜住并发瞬间的重复插入。
- DuplicateKeyException 捕获后要**重新抛出 ServiceException**（事务随异常回滚），不要吞掉。
- v1 注册**不操作 t_user_reuse**；等注销功能实现后再写复用记录。

### 第 6 步：Controller

**涉及文件**：`controller/UserInfoController.java`（贴原项目：register 与 has-username 都放在用户信息控制器）

```java
@RestController
@RequiredArgsConstructor
public class UserInfoController {
    private final UserLoginService userLoginService;

    @GetMapping("/api/user-service/has-username")
    public Result<Boolean> hasUsername(@RequestParam("username") String username) {
        return Results.success(userLoginService.hasUsername(username));
    }

    @PostMapping("/api/user-service/register")
    public Result<UserRegisterRespDTO> register(@RequestBody @Valid UserRegisterReqDTO requestParam) {
        return Results.success(userLoginService.register(requestParam));
    }
}
```

**要点**：has-username 返回 true 表示"可用"（前端据此提示"用户名可用"）；register 返回 UserRegisterRespDTO（username/realName/phone），不返回密码等敏感信息。

## 四、测试与验证

### 4.1 集成测试用例

测试类放 `src/test/java`，`@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.NONE)`，连本地 12306_user 库；测试用户名/手机号加唯一前缀（如 `test_` + 时间戳），结束后清理。

| 用例 | 操作 | 期望 |
| --- | --- | --- |
| 注册成功 | 调用 register | 返回 username/realName/phone；t_user/t_user_phone/t_user_mail 各 1 条且 del_flag=0；库中 password 是 BCrypt 密文（非明文） |
| 重复用户名 | 同名再注册 | 抛 ServiceException"用户名已存在"，无脏数据 |
| 重复手机号 | 不同用户名、同手机号 | 抛"手机号已注册"，事务回滚 |
| 参数校验失败 | 缺 username / 非法手机号 | 抛 MethodArgumentNotValidException，全局处理器返回失败 Result |
| 唯一索引兜底 | 绕过预检直接 insert 撞唯一索引 | DuplicateKeyException 转为业务异常，无残留数据 |

### 4.2 手动验证（本机执行）

```bash
curl -X POST http://localhost:9001/api/user-service/register \
  -H "Content-Type: application/json" \
  -d '{"username":"test001","password":"123456","realName":"张三","idType":1,"idCard":"110101199001011234","phone":"13800138000","mail":"test001@example.com"}'
```

期望响应：

```json
{"code":"0","message":null,"data":{"username":"test001","realName":"张三","phone":"13800138000"}}
```

再执行 `curl "http://localhost:9001/api/user-service/has-username?username=test001"` 应返回 false（已占用）；换一个未注册名字返回 true。

### 4.3 环境限制说明

当前沙箱环境 Tomcat 无法启动（NIO 回环连接受限），因此自动验证以 `mvn -pl services/user-services test` + 非 Web 启动冒烟（`--spring.main.web-application-type=none`）为准；接口联调请在你本机 `mvn -pl services/user-services spring-boot:run` 后执行。

## 五、验收标准与常见坑

### 验收清单

- [ ] `POST /api/user-service/register` 返回结构为 Result（code="0" 成功），数据为 username/realName/phone。
- [ ] 用户名、手机号、邮箱重复时返回明确业务错误文案，且库中无脏数据。
- [ ] 密码以 BCrypt 密文落库（长度 60，非明文）。
- [ ] 缺字段/非法格式返回失败 Result，不抛 500。
- [ ] `GET /api/user-service/has-username` 可用性语义正确（true=可用）。
- [ ] 集成测试全绿，`mvn compile` 零错误。

### 常见坑

1. **BCrypt 与字段长度**：密文固定 60 位，t_user.password 是 varchar(60)，别改成更长也别用 512 的旧 demo 口径。
2. **事务回滚**：`@Transactional(rollbackFor = Exception.class)` 必须显式声明，否则只有 RuntimeException 回滚。
3. **DuplicateKeyException 不能吞**：要捕获后重抛 ServiceException，让事务回滚并给前端友好文案。
4. **verifyState → verifyStatus**：注册 DTO 与实体字段名不一致，手动复制时最容易漏。
5. **复用表语义**：v1 的 t_user_reuse 只写不读；不要在注册时查它判可用性，否则"已注销用户名"会被误判为不可用。
6. **@Valid 别忘了加**：Controller 参数缺 @Valid 时注解不生效，所有校验静默失效。
7. **手机号预检别写成精确等于明文查询**：加密功能（v2）上线前先保持明文查询，后续配合 ShardingSphere 加密列方案调整。
