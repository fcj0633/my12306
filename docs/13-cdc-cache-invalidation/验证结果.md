# Canal＋RocketMQ 基础接入验证结果

执行日期：2026-10-11。范围为编译、少量逻辑测试、隔离库存的直接 SQL 占座和释放。不包含并发压测、长时间积压或故障矩阵。

## 已完成的改动

- 独立 `cdc-services`：Canal client/protocol 1.1.8，通过 TCP 拉取；原生 RocketMQ client 5.5.0 同步发送，只有全部 `SEND_OK` 才 ACK；失败 rollback、断线重连与退避。
- Ticket 独立 CDC 开关：默认关闭，不依赖支付 MQ/Feign 模式。消费异常重试，最多 16 次后 DLQ；提供 V1 body 文件重放工具。
- `InventoryCacheInvalidator`：事务事件与 CDC 共用，按基本区段精确映射重叠 OD；每次失效更新随机版本并删除缓存，实际释放删除令牌桶。原事务事件、重试、TTL、回填保护保留。
- Docker 配置、临时账号/库、Redis 命名空间、Topic/组隔离工具，以及启动、停机、位点恢复和 DLQ 说明。

参考原项目的事件消费者组织方式；库存表与消息协议按当前区段模型实现，没有移植其余票增量加减与事件提前去重。

## 真实链路

使用现有真实 MySQL（ROW/FULL Binlog）和 Redis；Canal Server 1.1.8、RocketMQ 5.5.0 在独立 Docker 项目运行；桥接和隔离 Ticket 实例在 Windows 宿主机运行。独立库只复制并迁移合法 train=1 夹具，共 5 站、960 个物理座位、3,840 条区段。被观察席别初始全程可售座位数 810。

提前创建并确认测试 Topic 路由，等待消费者分配队列，再预热 10 个 OD 缓存。直接 SQL 修改一个物理座位的基本区段 1，**没有写入业务失效事件**，保留原事件后台处理器。每次等待上限 10 秒，低于余票 27～30 秒 TTL。

| 操作 | commit 返回至观察到缓存失效 | commit 返回至全部 OD 重载并与 DB 核对正确 | 缓存与库存结果 |
|---|---:|---:|---|
| 占座：AVAILABLE→LOCKED | 1,731.04 ms | 2,083.21 ms | 6 个重叠 OD 被删除并从 810 变为 809；4 个相邻或无关 OD 保留，仍为 810 |
| 释放：LOCKED→AVAILABLE | 74.17 ms | 390.68 ms | 同样仅 6 个重叠 OD 删除；重载后全部恢复为 810，4 个其他 OD 保留 |

业务失效事件数为 0，说明此次失效来自 CDC。库存状态和缓存逐 OD 比对通过，测试工具在结束时恢复座位区段并清理命名空间。

原始逐 OD 数据、commit 返回时刻：[simple-chain.json](evidence/simple-chain.json)。桥接发送和消费者失效完成日志：[chain-observations.log](evidence/chain-observations.log)。这些日志记录发送/执行观察时刻，不能把 Binlog 事件时间或日志时间冒充精确 DB 提交时间；表中时间从 JDBC commit 返回处开始计量，包含轮询观测成本。

这只有一次占座和一次释放，第一笔还包含 MQ 客户端首次发送准备成本。不能计算可靠的 P99、生产传播 SLA，不能宣称吞吐提高。

## 接入过程中修正的问题

基础链路就绪前暴露并修复以下问题，失败后仅修复和重跑同一组简单步骤：

1. 新 Broker 卷属于 root，原镜像用户无法写 store；新增一次性权限初始化，Broker 继续用镜像用户运行。
2. Canal 使用 Apache ORO 正则，不支持 Java `Pattern.quote` 的 `\Q…\E`；显式校验库名后使用兼容的表过滤表达式。
3. Canal 引入的 Fastjson2 2.0.31 缺少 RocketMQ 5.5.0 所需编码方法；桥接显式使用与 Ticket 相同的 2.0.65，并加入编码回归测试。发生编码失败时位点未推进。
4. Broker 创建 Topic 后，NameServer 路由注册存在初始化等待；验证工具在提交 SQL 前确认路由和消费者队列已就绪，不扩大 10 秒失效等待窗口。

最终验证通过后未追加负载测试或服务故障实验。

## 清理核对与边界

四次接入调试使用的独立库、临时复制账号、Redis 前缀已核对无剩余；测试 Docker 项目、数据卷和网络已删除。临时凭据文件已删除。现有 `devcontext-postgres` 容器继续运行，业务库存未写入。清理检查与源码摘要：[cleanup-and-source.json](evidence/cleanup-and-source.json)。构建产物摘要：[build.json](evidence/build.json)。

默认配置仍关闭 CDC。启用后为双通路，允许重复、乱序失效；消息重试和 TTL 提供恢复手段，数据库区段条件占座承担防超卖。未验证 MQ/Canal 长暂停、提交后进程宕机、Binlog 过期或 Broker 崩溃，不能据此承诺所有故障场景不丢消息。

可用于简历的证据描述：

> 为区段库存接入 MySQL Binlog＋Canal＋RocketMQ 缓存失效兜底链路，保留事务失效事件形成双通路；设计发送确认后 ACK、失败回滚、重复消费与重试，并按基本区段精确失效重叠 OD 缓存。通过 12 项逻辑测试及真实占座/释放链路验证，确认绕过业务失效事件的 SQL 写入也能使余票缓存收敛。
