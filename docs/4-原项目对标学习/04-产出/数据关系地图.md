# 数据关系地图

> **作用**：从 D1 开始，把每条链路上遇到的数据对象逐个记下来，形成一张“谁拥有、有几个副本、哪些字段会变、哪些字段参与判断”的地图。
>
> **核心原则**：一个对象一张卡；跨边界必须记两边类名；看不懂的地方当场记成疑问。
>
> 最后更新：2026-09-14

---

## 一、怎么用

```text
D1–D13   每天随学随填，一个对象一行、一张卡，不求完整
        ↓
D4 / D8 / D11 / D13   四次进度检查（见第五节）
        ↓
D14      汇总成“全链路数据追踪卡”与“跨服务契约对照卡”
        ↓
面试     被问到“这个字段从哪来、有几个副本”时能直接答
```

**三条纪律**：

| 纪律 | 说明 |
| --- | --- |
| 当天记 | 数据细节隔天就忘，尤其是字段名和类名 |
| 记两边 | 跨 Feign / MQ 的对象，必须写清两边的类名与差异 |
| 记疑问 | 看不懂的地方不要放过，那通常就是真正的坑 |

## 二、数据对象清单模板

每天把当天遇到的对象追加到这张表里。

| # | 对象名 | 类型 | 归属服务 | 位置 | 是否会变 | 参与哪些业务判断 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | [示例] `SeatDO` | 实体 DO | 票务服务 | `T:dao/entity/` | 会变：`seat_status` | 余票统计、能否分配座位 |
| 2 | [示例] `PassengerRespDTO` | 远程契约 remote-dto | 用户服务 | `U:dto/resp/`、`T:remote/dto/` | 不变 | 乘车人归属校验 |

**类型只能填六类之一**：实体 DO / 请求 Req / 响应 Resp / 领域对象 domain / 远程契约 remote-dto / 消息事件 Event。

| 列 | 怎么填 |
| --- | --- |
| 对象名 | 类名或表名原文，不要写中文别名 |
| 归属服务 | 谁定义它、谁负责它的正确性 |
| 位置 | 包路径，沿用第八节的 `U:`/`T:`/`O:`/`P:`/`F:` 简写 |
| 是否会变 | 只读 / 会变（写明会变的字段） |
| 参与哪些业务判断 | 哪个判断读了它，判断的是什么 |

## 三、数据流转追踪卡模板

对**每一个会跨服务的数据对象**写一张。

```text
【数据卡 D__】对象名 [类型 / 归属服务]

产生：
变化：
跨边界：
落地：
规则：
疑问：
```

| 字段 | 要求 |
| --- | --- |
| 产生 | 谁 new 出来、从哪张表查出来、哪个接口返回 |
| 变化 | 被哪些方法改过，改的是哪几个字段 |
| 跨边界 | 走 Feign / MQ / 缓存；两边各叫什么类；字段是否一致 |
| 落地 | 最终落到哪张表；有没有第二份副本 |
| 规则 | 哪几个字段参与业务判断，判断的是什么 |
| 疑问 | 还不确定的地方，写下来带去验证 |

**合格标准**：合上代码，能按“产生 → 变化 → 跨边界 → 落地”把这条数据讲一遍。

## 四、跨服务契约对照卡模板

对**每一组跨服务同名类**写一张（原项目共 26 组，见主文档 5.5 排雷表）。

| 项 | 内容 |
| --- | --- |
| 契约名 | |
| 发起方 | 服务名 + 类名（含包路径） |
| 接收方 | 服务名 + 类名（含包路径） |
| 传递方式 | Feign / MQ |
| 发起方字段 | |
| 接收方字段 | |
| 类型差异 | 例如 `Long` vs `String`、`List<Long>` vs `List<String>` |
| 字段差异 | 哪一边多一个字段、哪一边少一个字段 |
| 转换位置 | 在哪段代码完成转换（写方法名即可） |
| 风险 | 一边改了另一边不知道，会产生什么后果 |

**为什么这张卡重要**：契约字段不一致不会报错，它只会在某次真实调用时静默丢字段或类型转换失败。

## 五、进度追踪表

| 检查点 | 应完成 | 达标线 | 自查 |
| --- | --- | --- | --- |
| D4 | 四条链路的数据对象清单 V1 | 累计 ≥ 10 个对象 | ☐ |
| D8 | 缓存与查询链路的数据对象 | 累计 ≥ 15 个 | ☐ |
| D11 | 购票与选座链路的数据对象 | 累计 ≥ 20 个 | ☐ |
| D13 | 订单与支付链路的数据对象 | 累计 ≥ 25 个 | ☐ |
| D14 | 汇总：全链路数据追踪卡 + 跨服务契约对照卡 | 两张卡完成 | ☐ |

**数量不是目的**：25 个对象里如果有 5 个你说不清“谁拥有”，不如只写 15 个但每个都能讲透。
