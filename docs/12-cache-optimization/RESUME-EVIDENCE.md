# 简历证据与表述边界

可采用的事实表述：

> 优化票务 Redis Cache Aside：为城市对、车次和搜索空结果增加短 TTL 缓存，按业务 Key 加锁双检并原子发布 Hash 与 TTL；通过余票随机版本校验阻止失效后的旧快照回填。使用真实 MySQL/Redis 进行 A/B 验证，50 并发、30 波空城市对击穿中，该缓存加载 SQL 从 1,500 次减少到 30 次，通过 11 项缓存正确性与故障检查。

这条强调回源与一致性证据，不需要把服务内空查询 QPS 当作全链路容量。

当前不适合写成“缓存优化全面提高性能”：50 并发热点 QPS 中位数下降 2.24%，P99 上升 9.89%；100 并发三轮 P99 上升 11.60%，尚未验收；两种混合查询吞吐约下降一成，高基数不存在 Key 吞吐下降约 73%。没有完成 Canal、Binlog、MQ 或 Caffeine，本轮也没有验证新的完整购票链路容量。

证据见 REPORT.md、RESULTS.md、FUNCTIONAL.json 和 evidence 原始记录。11 项检查及 1,500 次冷加载短验证使用最后修复代码；正式性能数据早于最后的冷加载竞态修复。全部源代码/编译产物摘要已保留，不将单机结果作为生产 SLA。
