## 观测定义

缓存指标按有限 family 分类。HTTP 请求和直接调用均有请求上下文，lookup 区分首次、重复及加载锁内查询；后两者不计入首次命中率。load 计数来自真正调用数据库加载器，不等于 miss 数；load.sql 使用实际 StatementHandler.prepare，父加载包含嵌套加载 SQL，跨类别不能重复相加。sql 总计数则每条准备语句仅计一次。

Redis 服务全局 keyspace_hits/misses 不作为本模块命中率；SQL数据只来自隔离票务连接。业务 Key、orderSn、请求 ID 不进入指标标签。commit 时间通过测试数据源的 Connection.commit 返回采集；异步失效的传播测量使用同 JVM 单调时钟。

## 隔离与复现

cache-ab.py 创建两套 codex_cache_test_<随机编号>_A/B 数据库，源业务库只读。实际 Redis 服务复用，但两个测试实例的 Spring Key 序列化与 Redisson NameMapper 均加入 codex:cache-ab:<唯一编号>: 前缀。实例退出仅扫描和删除其前缀；数据库清理验证严格格式后才删除。禁止 FLUSHDB/FLUSHALL。

基线和候选独立数据库，避免双方失效扫描器消费对方事件。固定 20 个数据库连接，Feign 模式，关闭孤儿恢复，真实库存失效处理开启。测试 HTTP 直连 Ticket，不包含 Gateway/User/Order；写入仅调用带真实车厢锁的本地事务与真实取消回调。

先 freeze、prepare、proof；问题基线确认后实施缓存行为修改，再运行交替 matrix。所有证据文件包含模型、场景、轮次、并发、计时窗口、逐操作分布、指标差值和错误分类。正常预计拒绝的无效车次按异常业务响应单独校验，不混入正常查询的成功容量。

| 类别 | 正常值 / 正常不存在 TTL | 加载和发布 | 读取、异常与失效入口 |
|---|---|---|---|
| 城市对车次 Hash | 270～330 秒 / 30 秒 | 城市对实际 Key 作为锁后缀，双检；完整 Hash 与 TTL 一次 Lua 发布 | TicketServiceImpl；空 Hash 保留字段仅缓存层识别，不进入外部响应 |
| 编码全集、车站城市映射 | 约 24 小时 ±10% / 空快照 30 秒 | 各自全量锁；完整快照原子替换 | 查询校验、城市映射；已存在完整快照但编码缺失时直接返回现有业务错误 |
| 车次信息 | 原 15 天 ±10% / 30 秒 | RedisCacheHelper.train 统一入口，按 Key 锁和双检 | 查询、购票参数校验、元数据准备、余票加载；不存在车次保持原业务错误 |
| 票价、地区与车站搜索、全站列表 | 原 15 天 ±10% / 30 秒 | safeGet 按 Key 锁和双检，String 内容和 TTL 原子 SET | 正常空列表编码为空标记；数据库、Redis、解析异常继续传播，不写成不存在 |
| 动态余票 | 27～30 秒 / 合法零余票为正常值 | OD 锁与双检；数据库前取得随机版本，比较版本后发布完整 Hash 与 TTL | 只加载请求 OD；失效原子更新随机版本并删除所有重叠 OD；最多重新查询一次，持续竞争放弃缓存回填 |
| 余票版本 | 120 秒 | miss 时原子取得/初始化；每次失效尝试产生新随机令牌 | 热命中不读取版本；随机令牌避免缺失、重复或迟到事件恢复旧版本 |
| 区段令牌桶 | 原 10 分钟 | 保持现有容量准入及失效重装 | 本轮只审计，不改策略 |

旧版本无法解释新增空值标记，发布需要协调停止旧实例的缓存读写。已经存在的永久 Hash 不会仅因新代码命中而获得 TTL：切换时用独立 CacheTtlMigrationTool 只读审计，再按环境选择修复 TTL 或清理静态缓存。工具的 apply 仅处理 TTL=-1 的票务缓存，不延长已有 TTL，不处理锁或令牌桶。本轮只在测试命名空间验证修复，没有操作业务缓存。

## 指标解释与成本边界

A 的余票加载计时包含无条件缓存发布，B 的 diagnosed 加载计时只覆盖元数据读取和库存聚合，不包含前后的版本取得、条件发布。因此 load Timer 可用于各自诊断，不直接用于宣称整个重建耗时下降；对比以请求耗时、实际 SQL 分类、波次耗时为准。父加载 SQL 包含嵌套加载，不能与子加载相加。

A 在一次余票加载中通常查询车次和库存各一条 SQL；B 共享车次缓存后通常只执行库存聚合。这是元数据 SQL 减少。B 在失效竞争下可能重复库存聚合，不能从总 SQL 减少推导数据库成本或混合吞吐必然降低。

相对于 A 的一次 Hash 发布，B 的每次余票加载还包含版本 Lua 和缓存车次 GET，版本变化可能再加载一次。失效一次 Lua 替换批量 DEL，虽然网络往返仍是一次，但服务器还要为每个受影响 OD 设置版本并维持额外 Key。不存在 Key 每次都不同的高基数穿透没有复用收益，却增加锁、空值写入及临时 Key，必须单独报告成本。

首次三轮七场景测试保留了测量前配对订单建立时的少量异步事件重叠，原始删除/事件尝试计数可能包含这些初始化处理。后续驱动明确在测量前排空事件。混合传播延迟只使用与本轮 commit 按订单、事件关联成功的样本；不将额外处理尝试当成额外业务提交。


最后冷加载验证发现并修复 HMGET→EXISTS 之间的快照发布竞态：不能看到 EXISTS=true 就沿用此前的空字段判不存在，应重新读取已发布快照。该修复仅在首读缺字段路径执行，不给正常热命中新增 Redis 请求。30 波、1,500 请求通过；原失败组的 16 次误拒绝保留。
