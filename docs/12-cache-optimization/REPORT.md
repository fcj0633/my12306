# 缓存专项最终报告：第 1～3 项

本轮基于开始时的区段库存工作区建立 A 组，对同一诊断版本实施 Cache Aside 优化作为 B 组。使用真实 MySQL、Redis 和独立数据库/Key 前缀。没有引入 Caffeine、Canal、Binlog 或新 MQ，没有修改库存模型或外部接口。

当前版本原本已有单 OD 各席别一次库存聚合、30 秒余票 TTL、OD 加载锁与事务失效事件重试。本轮保留这些能力，主要新增空结果缓存、按城市对独立加载锁、快照 TTL 与长期 TTL 抖动、统一车次加载入口，以及防止失效后旧快照回填的随机版本校验。

## 结束状态与未验收项目

按用户 2026-10-11 的要求快速结束长测。代码、三轮主要场景、50 并发五轮严格 HTTP、100 并发三轮、30 波单 Key 击穿和 11 项正确性检查已完成，但不能声明整个计划全部验收通过。100 并发 P99 上升 11.60%，未完成规定的五轮补测与回退归因；本次不追加测试。

独立多 Key 并行屏障、缩短 TTL 集中到期实验、额外高基数 Key 数量/版本 Key 数量探针与预热 ROI 没有完成正式对照。已有全量回归为 92 项、0 失败、0 错误、2 跳过；最后冷加载修复后完成编译、真实 1,500 请求验证与 11 项检查，没有重新运行全量回归。热点与混合正式性能在该冷路径修复之前测得，修复不改变正常热命中路径，仍不能代替最终版本完整性能验收。

主要场景 50 并发、60 秒、A/B 交替三轮；热点 HTTP 以严格发送到完整响应读取的口径补到五轮，100 并发单独列出。下表为逐轮中位数；完整范围、平均和 P50/P95/P99 见 RESULTS.md，全部指标与原始延迟见 evidence。服务内调用不等于 HTTP 或全链路购票容量。

热点组没有证实性能提升。按计划的中位数门槛检查 QPS 下降 5%、P99 上升 10%；全部轮次保留，包括较慢的首轮。历史和旧计时口径的组不用于替换严格口径的验收结果。绝对吞吐随测量阶段有明显波动，不能把单机数值当作生产容量承诺。

- 50 并发热点：QPS -2.24%，P99 +9.89%；满足本机容差门槛，每组 5 轮。
- 100 并发热点：QPS -4.19%，P99 +11.60%；未满足门槛，不能验收，每组 3 轮。

重复查询相同不存在数据时，短 TTL 空值将回源从每请求降为每 TTL 窗口加载；这些场景的改善来自空值复用，不能推广到合法热点或正常购票。高基数 unique-train 每次使用不同 ID，没有复用收益，B 增加加载锁和空值写入，吞吐明显下降。空值缓存不是高基数流量的限流替代方案。

## 读写混合的实际代价

混合负载为 80% 查询、10% 单票占座、10% 真实取消。占座经过真实车厢锁和事务代理，取消使用真实回调；乘客与车次元数据作为合法夹具直接传入事务，不含远程 User/Order 建单、Gateway 或完整购票校验。

B 的普通加载通常少一次车次元数据 SQL，但失效竞争会重复执行成本更高的库存聚合。两种混合场景查询吞吐约下降一成，不能宣称混合性能提升，也不能仅凭总 SQL 减少宣称数据库成本下降。版本机制属于一致性修复；没有独立消融实验，不能把全部下降百分比归因于某一个改动。

余票加载指标 A 包含发布、B 不包含版本获取与条件发布，不能直接比较 Timer 并宣称单次完整重建变便宜。每轮实际 SQL、加载次数、删除调用及涉及/实际删除 Key 数、重查次数均在 RESULTS.json 和原始文件中。库存聚合仍只针对请求 OD，一次按席别分组；没有整车 OD 在线预热的新收益。

## 正确性、冷加载与故障证据

B 正确性检查通过 11 项：negative-expiry-rediscovers-data、negative-hash-expiry-rediscovers-data、database-timeout-not-cached、Redis-client-outage-not-negative、parse-error-not-negative、changed-missing-duplicate-nonce-rejected、hash-replacement-finite-TTL、overlap-deleted-adjacent-preserved、outbox-retry-converges、legacy-permanent-TTL-audit-and-idempotent-repair、deterministic-refill-race。
确定性回填竞争：B 缓存 809、数据库 809，没有发布旧快照。
B 20 个停止后续写入的购票/取消脉冲：平均 171.14 ms，P99 233.48 ms；活动区段 0。连续三次与数据库相符才收敛，耗时包括数据库对账和轮询。

最后的多 Key 冷加载首次 B 组出现 16 次合法编码误拒绝：HMGET 得到空值后，另一个线程发布快照，EXISTS 返回存在，当前线程却沿用旧空结果抛错。编码校验和城市映射都改为在快照已存在时重新读取。修复后 50 同时请求、30 波、1,500 次全部成功。失败原始文件保留，不宣称多 Key 冷加载性能提升。

空城市对 30 波击穿的该缓存加载 SQL：A 1,500 条、B 30 条，减少 98%。这是该加载器的 SQL，不是整个 MySQL 服务器所有语句。

单 Key 击穿分别执行 50 同时到达请求、30 波，原始文件保留加载/锁内命中和 SQL。空城市对 A 未缓存空结果，会在锁内连续加载；B 在每波同一 TTL 窗口内合并为一个成功加载。余票 A 原本已有加载锁，其合并能力不属于本轮新增收益。

失效事件按 orderSn 与原事务 commit 返回关联。连续混合期间的 commit→invalidation 与停止写入后的 commit→correct 分别报告，不将事件创建时间当作提交时间。故障仅注入隔离客户端和调用，验证 Redis 客户端异常、加载超时、持久化事件保留与恢复重试；没有停止共享 Redis/MySQL，不代替服务重启、网络分区或 CDC 故障实验。

## 交付、发布边界与剩余判断

AUDIT.md 为缓存清单和指标口径，RUNBOOK.md 为复现和切换步骤，RESULTS.md/RESULTS.json 为逐轮正式数据，FUNCTIONAL.json 和 evidence 为正确性与原始证据。预热工具默认并发 2、10 OD/秒，复用正常加载器；没有生产周期性整车预热。

空值标记要求协调升级，旧实例不能同时读取新标记。遗留永久缓存由只读审计工具检查，显式 apply 仅为 TTL=-1 的票务缓存补 TTL，不延长已有 TTL；本轮只在测试前缀验证，不处理业务 Redis。源夹具存在历史冲突，报告保留；仅复制 Train 1 合法库存，未修复或迁移业务库。

可用于简历的是：识别并修复空结果穿透、加载锁粒度与失效后旧值回填，使用真实 Redis/MySQL、多轮 A/B 和故障注入验证。不能写成热点或混合链路全面提速，不能把服务内空查询 QPS 写成全链路购票 QPS，不能写成 Canal/MQ 已完成或余票强一致。

测试收尾：本轮日志记录的 23 个 Redis 命名空间检查到 27 个遗留 Key，均已删除；两套脚本创建的隔离数据库已删除。业务数据库和业务 Redis Key 未参与清理。
